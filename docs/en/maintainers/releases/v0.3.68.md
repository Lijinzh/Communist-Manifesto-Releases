# AutoClipboard v0.3.68 formal Windows / Linux release

Status: formal Windows x64, Linux amd64, and V3 firmware `0.3.68` release; macOS remains deferred.

- Source tag: `v0.3.68`
- Desktop source commit: `bb0ebababb70a16660b5f13dce5335df01b7c314`
- Firmware source commit: `88f55b4b05d7bc6af4af2a5fc1c1ddf23cf03057`
- Component versions: AutoClipboard `0.3.68`, Skill `0.3.68`, V3 firmware `0.3.68`
- Build path: native local Windows build and native dedicated Linux-node build, both bound to the same full commit

<!-- section:s002 -->
## Highlights

- Released the account center, desktop login session, pixel-theme backgrounds and raised-platform styling, premium voice gateway path, and software self-update fixes.
- Both Windows and Linux installers passed their complete PyInstaller, packaged Maintenance, esptool runtime, and GUI smoke gates.
- V3 normal mode uses 160 MHz, 104/100/20 Hz, and an approximately 15–22.5 ms BLE connection; Halo/game mode temporarily raises these to 240 MHz, 208/200/50 Hz, and approximately 7.5–15 ms.
- BLE transmit power is `+6 dBm`. New factory defaults use LCD `150/255`, ring `56/255`, a two-minute display timeout, and a 30-minute Deep Sleep policy while migrations preserve user-customized values.
- Linux shell scripts are pinned to LF so Git archives and Windows checkouts cannot corrupt `pipefail` into `pipefail\r`.

## Self-update and public publication acceptance

- Windows completed a real startup automatic check from installed `0.3.67`, public Release download and SHA-256 validation, installer launch, orderly exit, and restart on `0.3.68`; the registry, running process, and software settings UI all confirmed `0.3.68`.
- Key Windows settings remained enabled or selected: Simplified Chinese, classic theme, Agent panel, strong alerts, global shortcut, and disabled global Typeless mode. The settings file changed bytes during normal application saving, so this release does not claim byte-for-byte preservation as proven.
- Linux was confirmed to have `0.3.67` installed, and the formal updater code successfully discovered, downloaded, and validated the `0.3.68` DEB version, size, and SHA-256. The actual install still requires desktop user `lee` to approve `pkexec` in the graphical session; the dedicated `buildbot` account cannot impersonate that user or elevate, so Linux automatic installation is not claimed as passed.
- V3 firmware was updated from `0.3.67` to `0.3.68` on Linux `/dev/ttyACM1`, `board=v3`, `sid=A1EA`. Only the application region at `0x10000` was written; the written hash and version readback passed. The complete serial smoke passed, and a 30-second BLE/IMU run received 565 frames at 18.83 Hz with no sequence gaps, duplicates, watchdog expiry, or reset suspicions. One optional 250 ms status poll timed out without interrupting the notify stream.
- GitHub and Gitee both expose `v0.3.68` as latest with the same five asset names and sizes; anonymous Gitee API access and every attachment download URL were verified readable.
